\section{Repository, models, and data}
The implementation is stored at \url{https://github.com/AhmadAkhtar007/pa2-small-model-alignment}. It implements response-masked supervised fine-tuning (SFT), two manual Direct Preference Optimization (DPO) experiments, and a separate TRL/LoRA persona experiment. The repository and checkpoint sources are currently private; course reviewers require access before submission.

The main model is \texttt{Qwen/Qwen2.5-0.5B}. SFT used the first user/assistant turn from UltraChat. Both manual DPO policies started independently from the same best SFT checkpoint. HH used strictly single-turn Anthropic HH-RLHF pairs, while the other run used UltraFeedback binarized pairs. Duplicate prompts were removed before seeded selection and splitting. Persona training used \texttt{HuggingFaceTB/SmolLM2-360M-Instruct} and the supplied Ramsay-style preferences.

\section{Implementation and parameter choices}
Manual SFT and DPO use custom PyTorch loops; TRL's DPOTrainer is used only for persona tuning. Padding and prompt positions are excluded from response scoring. An EOS token is appended before truncation. SFT minimizes the negative response log probability averaged across scored tokens. Accumulation groups are normalized by the total scored-token count, including the final partial group.

For DPO, let $s_\theta(x,y)$ denote the sum of response-token log probabilities. The batch objective averages
\[
 -\log\sigma\left(\beta\left[
 s_\theta(x,y_w)-s_\theta(x,y_l)-s_{\mathrm{ref}}(x,y_w)+s_{\mathrm{ref}}(x,y_l)
 \right]\right).
\]
The reference is frozen and evaluated without gradients. Validation preference accuracy uses the strict comparison between the chosen and rejected implicit rewards. Best DPO checkpoints are selected by this accuracy; best SFT is selected by validation loss.

The shared Qwen prompt is \texttt{\#\#\# Instruction:} followed by the instruction, two newlines, and \texttt{\#\#\# Response:}. Formatted prompts retain their last 256 tokens. This cap was also applied to SFT and evaluation for consistency, although it can remove context from long instructions. Persona generation uses the instruct tokenizer's chat template.

The manual DPO learning rate, beta, epoch count, and effective batch size follow the guide recipe. AdamW is one of the allowed DPO optimizers. LoRA settings limit trainable capacity on the small preference set; they were not established as optimal through a parameter sweep. Zero dropout avoids introducing stochastic differences in preference scoring.

The initial greedy sanity outputs contained repeated phrases and several answers reached the 256-token generation cap. \section{Interpretation, error analysis, and limitations}
Initial sanity responses establish a limitation rather than a quality improvement. Both SFT and HH DPO sometimes supplied harmful assistance after a superficial disclaimer. Qwen responses showed repetitive completions and misunderstandings of some prompts. Persona responses were often close to the unadapted instruct baseline; the initial three samples did not establish strong persona fidelity. Some cooking responses omitted important safety checks or contained dubious advice. These observations are based on a few samples and must not be presented as aggregate evaluation results.

A higher preference-validation accuracy does not by itself establish better responses, safer behavior, or a higher judged win rate. The final analysis must distinguish observations from explanations such as dataset mismatch, limited model capacity, insufficient style steering, or decoding effects. One seed, small evaluation sets, a synthetic HH benchmark, judge bias, prompt truncation, and failed interactive sessions limit interpretation. Saved batch runs removed dependence on editor inactivity, but do not guarantee infrastructure cannot fail.
