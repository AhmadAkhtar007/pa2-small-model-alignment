\section{Implementation and parameter choices}
The loss scores only response tokens: prompt and padding tokens are masked out, and EOS is appended before truncation. SFT divides the total response-token negative log likelihood by the number of scored tokens in each accumulation group, including the final partial group. DPO sums response log probabilities $s_\theta(x,y)$ and averages the following objective over pairs:
\[
-\log\sigma\!\left(\beta\left[s_\theta(x,y_w)-s_\theta(x,y_l)-s_{\rm ref}(x,y_w)+s_{\rm ref}(x,y_l)\right]\right).
\]
The reference model runs without gradients. A validation pair counts as correct only when the chosen response has a strictly higher implicit reward than the rejected response. SFT checkpoint selection uses the lowest validation token loss; DPO selection uses the highest validation preference accuracy. These objectives and training loops are implemented in PyTorch. Only the persona experiment uses TRL's DPOTrainer.

Qwen uses the template \verb|### Instruction:\n{instruction}\n\n### Response:\n|, where \verb|\n| denotes a newline. SFT and evaluation both retain the last 256 tokens of the formatted prompt, which can discard part of a long instruction. SmolLM2 uses its instruct chat template. The main DPO runs follow the guide's AdamW option, learning rate, beta, and effective batch size.

For persona tuning, rank 8 keeps the adapter small. Adapting the attention query, key, value, and output projections allows style changes while the base weights remain frozen. The learning rate of $5\times10^{-5}$ and three configured epochs were initial settings for the 198 training pairs; no tuning sweep was run. A microbatch of 1 limits memory use, with eight-step accumulation giving an effective batch of 8. The model loads in FP32 and trains with FP16 mixed precision; BF16 is disabled. Validation preference accuracy reached 100\% on 22 pairs, while held-out style scores showed no improvement.

Source was transferred to Kaggle through a Google Drive ZIP and is versioned on GitHub. Base responses were generated after training from the untouched base checkpoint. The persona run completed 72 updates; its final Trainer state records epoch 2.889, with three epochs configured.

Initial greedy outputs repeated phrases, so final decoding uses a repetition penalty of 1.1 and no-repeat trigram size 3. Before generating the full sets, three responses were inspected for each of seven model/set combinations. All comparisons use the same settings on both sides: greedy decoding, one beam, seed 42, and a maximum of 256 new tokens. Temperature, top-p, and length penalty remain at 1.0.

\section{Interpretation and error analysis}
\textbf{HH.} Falling validation loss and a rising reward margin show that HH learned to favor chosen responses over rejected ones. The selected step-400 checkpoint reached 62.5\% validation preference accuracy, then won 168 comparisons and lost 95 against SFT on the synthetic HH set. Some winning responses are clearer and shorter. HH explains satellite imagery more clearly on \texttt{hh-eval-42-0002}; on \texttt{hh-eval-42-0004}, both models refuse harassment, but HH is more concise. Safety is still inconsistent. HH gives harmful assistance on \texttt{hh-eval-42-0001}, and both models fail to refuse on \texttt{hh-eval-42-0000}. The 63.88\% decisive win rate therefore measures the judge's overall preference, including clarity, rather than the proportion of safe refusals.

\textbf{UF.} UF reached validation DPO loss 0.585609 and preference accuracy 68.9\%, better numerical values than HH's. Yet it lost 138 AlpacaEval comparisons against SFT and won 95. Each model was validated on its own preference dataset, so those validation scores cannot directly compare general usefulness. On \texttt{alpaca-42-0002}, SFT follows the sports-commentator instruction more closely while UF mixes incompatible sports details. UF's validation gains did not prevent this instruction-following error. It maintains character more consistently on \texttt{alpaca-42-0003}, while both models misinterpret an idiom on \texttt{alpaca-42-0000}. Overall, its 40.77\% decisive win rate shows weaker judged performance than SFT on this AlpacaEval subset.

\textbf{Persona.} The adapter and baseline often give similarly bland, truncated, or incorrect answers. Cooking examples contain factual mistakes, and style scores remain close to the minimum. The answers to \texttt{persona-03} are identical. Although the selected adapter scores perfectly on the small preference-validation set, that result does not carry over to the held-out style prompts.

Both main DPO runs started from the same SFT checkpoint and used beta 0.1, the same learning rate, and a one-epoch budget. Decoding was matched within each comparison. Both learned their training preferences, but only HH improved judged performance on its evaluation set. The examples suggest that HH's clarity gains helped on the synthetic HH prompts, while UF's learned preferences transferred less well to AlpacaEval instructions. This is a possible explanation, with dataset choice and evaluation task changing together. A direct HH-versus-UF ranking would require testing both on the same set. The training curves alone do not establish overfitting, and the examples do not measure how frequent each behavior is.

\section{Limitations and reproducibility}
All comparisons use one judge, Gemini 3.6 Flash, whose decisions may favor a response's position, length, or formatting. Response order was randomized, but pairs were not judged again with positions reversed. Human assessment could therefore produce different results. Each main evaluation has 300 prompts; the HH set is synthetic, and persona evaluation has only 12 prompts. These sizes limit how broadly the results apply. Training and subset selection use only seed 42, so the experiments do not measure variation across seeds.

The experiments ran on Kaggle T4 $\times2$ with 512-token sequences, a 256-token prompt cap, and at most 256 generated tokens. These limits can remove context or cut answers short. The compute budget covered one epoch per main track and three configured persona epochs, without multi-seed runs or hyperparameter and decoding ablations. SFT was rerun after an interactive session expired; all reported SFT results come from the preserved completed run. Invalid judge responses were retried as described in Section 5, leaving zero unresolved comparisons.
